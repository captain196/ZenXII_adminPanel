# SchoolSync — scheduled maintenance (crontab entries).
#
# Install on the host that has PHP + access to the Firestore service
# account JSON. Each entry routes through run_scheduled.php so every
# run lands in `scheduled_job_runs/{runId}` and any failure raises a
# fee_alerts record (which fires Slack/email if configured).
#
# Replace SCH_D94FE8F7AD with your live schoolId and YYYY-YY with the
# active session. One line per school; loop in a wrapper if you run a
# multi-tenant host.
#
# Columns:  m h dom mon dow  command

# ── DAILY 02:15 — reconcile demands vs defaulters ──────────────────
15 2 * * * /usr/bin/php /var/www/Grader/school/scripts/run_scheduled.php --job=reconcile --schoolId=SCH_D94FE8F7AD --session=2026-27 >> /var/log/schoolsync/reconcile.log 2>&1

# ── WEEKLY Sunday 03:00 — cross-system integrity audit ─────────────
0 3 * * 0 /usr/bin/php /var/www/Grader/school/scripts/run_scheduled.php --job=integrity --schoolId=SCH_D94FE8F7AD --session=2026-27 >> /var/log/schoolsync/integrity.log 2>&1

# ── DAILY 00:20 — make today's published timetable visible to the ──
#    Teacher and Parent apps.  PLATFORM-WIDE: ONE LINE, ALL SCHOOLS.
#
#    NOTE THE ABSENCE OF --schoolId. This is deliberate and is the whole
#    point: ZenX is multi-tenant, so timetable delivery must not be a
#    per-customer deployment task. The job discovers eligible tenants from
#    the `schools` collection and each one's session from its own
#    `currentSession`, so a school onboarded tomorrow is picked up by the
#    next run with no cron edit, no deployment and no code change.
#
#    The office reads the canonical timetable versions; the apps read a
#    separate copy that has to be written for them. Publishing writes it
#    itself when the timetable starts the SAME day — so the gap this
#    closes is the timetable published today to start later, which
#    otherwise reaches nobody. Runs before the school day so a version
#    that becomes effective this morning is in place in time.
#
#    Safe to run repeatedly and safe to MISS: it asks "what applies
#    today", writes only what differs, and never deletes. A skipped night
#    is repaired by the next run. One school failing does not stop the
#    others — each is processed in isolation and recorded separately in
#    scheduled_job_runs/TTP_{date}_{school}_{session}.
#
#    Exit codes: 0 = every eligible tenant processed or correctly skipped.
#                2 = at least one tenant FAILED (the others still ran), or
#                    the tenant list itself could not be read — page someone.
#
#    Add --schoolId/--session only for a targeted or recovery run.
20 0 * * * /usr/bin/php /var/www/Grader/school/scripts/run_scheduled.php --job=timetable >> /var/log/schoolsync/timetable.log 2>&1
