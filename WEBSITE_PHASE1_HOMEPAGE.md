# Section 6 — Real-Time Sync Engine (The Differentiator)

**1. Section Name:** Real-Time Sync Showcase

**2. Headline:**
**Built on a real-time engine. Updates propagate everywhere, instantly.**

**3. Subheadline:**
What happens in one app appears in the others within a second. No batch jobs. No nightly syncs. No "please refresh to see the latest data."

**4. Body Content:**

[Brand] is built on a cloud-native real-time engine — the same class of infrastructure that powers messaging apps used by billions of people. When a teacher marks a student absent at 9:05 AM, the parent's home screen shows that absence at 9:05 AM. When a parent pays fees online, the principal's collection dashboard ticks up before the parent has put down their phone.

This isn't a feature. It's the foundation. And it changes how schools operate.

**Four illustrative workflows (timeline-style block):**

### Workflow 1 — Online Fee Payment
> Parent taps **Pay** → Razorpay processes the transaction → Admin Panel records the receipt → Teacher App's class-fee counter updates → Parent receives push receipt.
> **End-to-end latency: under 2 seconds.**

### Workflow 2 — Homework Assignment
> Teacher uploads a worksheet from their phone → Cloud Storage validates the file → Firestore broadcasts to every parent in the class → Parent App displays the new homework with attachment ready to download.
> **End-to-end latency: under 3 seconds.**

### Workflow 3 — Attendance Marking
> Teacher taps **Present/Absent/Tardy** → Per-student records and monthly summary write → Parent App reflects today's status + updated calendar → SMS/push optional for absences.
> **End-to-end latency: under 1 second.**

### Workflow 4 — Behaviour Flag
> Teacher long-presses a student → picks severity → submits → Parent receives push notification → Counsellor sees the flag in the admin alerts feed.
> **End-to-end latency: under 2 seconds.**

**5. CTA Text:**
- Primary button: **See the engine in action** (opens a 60-second product video or anchors to demo booking)
- Text link: *Read the technical brief* → (links to a dedicated infrastructure page)

**6. Suggested UI Structure:**
- **Layout:** Vertical timeline / flow diagram. Each workflow is a horizontal row with three columns: origin device icon → arrow with animated dots → destination device icon. Below each row, a 1-line outcome statement.
- **Background:** Dark mode panel (deep navy) to make the animated data-flow dots visually pop.
- **Animation:** Tiny accent-colored dots animate along the connecting arrows in a loop, suggesting live data flow.
- **Section eyebrow:** Above the headline, a small uppercase label in accent color: "REAL-TIME ENGINE".
- **Optional embed:** Below the four workflows, embed a short looping video (15–30 seconds) showing the three apps side-by-side reacting to the same event.

# Cross-Section Style Guide (For Designer Handoff)

Below is a quick style reference to keep the homepage cohesive.

## Typography
- **Display:** Premium geometric sans (e.g., Söhne, Inter Display, GT Walsheim, or a paid serif like Tiempos Headline for an editorial feel)
- **Body:** Inter, IBM Plex Sans, or system font stack for performance
- **Numerals:** Tabular numerals for stat blocks

## Color Palette (Suggested)
- **Primary (Brand):** Deep teal (#0F766E) or deep indigo (#3730A3)
- **Accent (CTA / energy):** Amber (#F59E0B) or coral
- **Neutral light:** #FAFAFA, #F5F5F5
- **Neutral dark:** #0A0F1C, #111827
- **Each app gets a sub-accent:** Admin = indigo, Teacher = teal, Parent = amber

## Imagery
- Real product screenshots wherever possible (Sections 2, 8, 9, 10, 12)
- Avoid stock photography of "happy students" — use abstract data visualisations and product mockups instead. Premium SaaS sites lean on product imagery, not stock people.
- Where photography is used (e.g., testimonial portraits), commission real customer photography.

## Motion
- Subtle hover lifts on cards
- Animated data flow dots in Sections 4 and 6
- Number counters tick up on scroll-into-view in Sections 3 and 16
- No autoplay video. Reserve video for opt-in CTAs.

## Section Rhythm
- Alternate light and dark sections to create visual rhythm: hero (dark) → trust (light) → problem (off-white) → ecosystem (light) → real-time (dark) → modules (light) → admin (light) → teacher (light) → parent (light) → multi-role (light) → analytics (dark) → security (light) → audience (light) → why (light) → outcomes (light) → FAQ (light) → final CTA (dark) → footer (dark).
